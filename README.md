# مدیریت محتوای هوشمند — AI Content Manager

افزونه‌ای فارسی برای تولید دستی و کمپین کلمه کلیدی: موضوع‌یابی مستقل، پژوهش وب با بررسی شواهد و ساخت پیش‌نویس قابل ویرایش در همان صف WordPress. شروع هزینه‌دار کمپین تأیید جداگانه می‌خواهد و تمام خروجی‌ها نیازمند بازبینی انسانی‌اند؛ هیچ نوشته‌ای خودکار منتشر نمی‌شود.

- نسخه افزونه: **۰.۷.۲** (`0.7.2`)
- نسخه ساختار دیتابیس: **۱.۴.۰** (`1.4.0`)
- حداقل اعلام‌شده: WordPress ۶.۰ و PHP ۷.۴؛ اجرای واقعی روی همه این نسخه‌ها تأیید نشده است.

## امکانات اجراشده

- کمپین غیرفعال بر اساس یک کلمه کلیدی، پیش‌فرض سه مقاله مستقل و روزی یک مقاله؛ شروع، توقف، ادامه، پایان، تغییر صریح سقف هزینه و نمایش سابقه در همان سه تب.
- موضوع‌یابی و پژوهش با Responses و ابزار جست‌وجوی وب، بررسی محلی تنوع، دریافت امن دو یا سه منبع و تطبیق نقل‌قول شواهد پیش از تولید. URL، عنوان واقعی صفحه و زمان دسترسی در جزئیات صف قابل بررسی‌اند.
- اجرای یک مرحله در هر worker، قفل مشترک با تولید دستی، شناسه تلاش و lease، نگهداری پاسخ پیش از اعمال و ادامه مرحله ناقص همان مقاله/پیش‌نویس بدون تولید دوباره.
- کنترل مصرف مشترک برای موضوع‌یابی، پژوهش و تولید؛ برآورد و رزرو دلار، توکن و فراخوانی جست‌وجو، سقف هر کمپین/مقاله و حفظ رزرو مصرف نامشخص.
- نمایش پیشنهاد ذخیره‌شده و گزارش هر پیشنهاد با پرسش، زاویه، نتیجه، دلیل، امتیاز و شناسه مرجع؛ بررسی مجدد محلی بدون شبکه یا مصرف تازه. موضوع‌یابی تازه کنترل هزینه‌دار جدا با سقف دو تلاش دارد.
- سه تب فارسی «تولید محتوا»، «مدیریت صف» و «تنظیمات».
- ثبت یک موضوع یا چند موضوع مستقل با اطلاعات مشترک، کنترل تکرار و اعتبارسنجی ورودی.
- تولید دستی هر مقاله با سرویس واحد OpenAI و نگهداری خروجی ساختاریافته و سابقه مصرف؛ تولید می‌تواند هزینه API داشته باشد.
- محدودیت درخواست و توکن، رزرو مصرف، گزارش مصرف و بازیابی آیتم‌های متوقف‌شده.
- پیش‌نمایش خروجی، زباله‌دان نرم صف و بازگردانی آیتم؛ محتوای تولیدشده و سابقه مصرف حفظ می‌شوند.
- ساخت دستی پیش‌نویس نوشته و برگه، رابطه پایدار با آیتم صف و جلوگیری از ایجاد پیش‌نویس تکراری. ساخت پیش‌نویس محصول پشتیبانی نمی‌شود.
- تخصیص زبان پیش‌نویس در صورت فعال‌بودن WPML؛ تولید ترجمه خودکار انجام نمی‌شود.
- تکمیل اختیاری فیلدهای خالی Yoast هنگام ساخت پیش‌نویس و مقایسه/اعمال دستی عبارت اصلی و توضیحات متا روی پیش‌نویس مرتبط.
- اصلاح پیشنهاد عبارت اصلی قدیمی بدون تولید مجدد: پیشنهاد اصلاح‌شده در `payload.seo_review` نگه‌داری می‌شود و `generated_output` اصلی برای سابقه حفظ می‌شود. ابتدا ذخیره پیشنهاد و سپس اعمال از مقایسه تازه انجام می‌شود.
- حفظ مقدار دستی Yoast مگر با انتخاب صریح بازنویسی، تشخیص تعارض از زمان مقایسه، کنترل مجوز و nonce و پردازش مستقل هر فیلد.
- دسته‌بندی متناسب با زبان محتوا، جداسازی انتخاب خالی از انتخاب نامعتبر و حفظ ورودی خطادار. زبان پیش‌نویس پیش از دسته‌بندی تنظیم می‌شود و termهای واقعی پس از پایان هر دو دوباره خوانده می‌شوند.
- بررسی پیش‌نویس‌های ready و مسیر دستی «بررسی و اصلاح دسته‌بندی» با مقایسه، تأیید صریح و تشخیص تعارض؛ تغییر دستی خودکار بازنویسی نمی‌شود. انتخاب اصلی صف حفظ و در جزئیات نمایش داده می‌شود.

## موارد هنوز پیاده‌سازی‌نشده

انتشار خودکار/زمان‌بندی‌شده، ساخت تصویر شاخص، ترجمه، پژوهش برای درخواست‌های دستی قدیمی، ممیزی عمومی سئوی نوشته‌های موجود و جریان کامل محتوای WooCommerce هنوز اجرا نشده‌اند. اجرای خودکار فقط مربوط به کمپین‌هایی است که صریحاً شروع شده‌اند؛ صف دستی خودکار شروع نمی‌شود. این مخزن گردش‌کار استقرار خودکار ندارد.

## نصب دستی

۱. ابتدا روی WordPress تستی مستقل و دارای نسخه پشتیبان آزمایش کنید. برای تست اصلاح سئو می‌توان از آیتم تولیدشده و پیش‌نویس موجود استفاده کرد و دسترسی OpenAI را مسدود نگه داشت.

۲. از سورس ZIP محلی بسازید یا پوشه افزونه را با نام `ai-content-manager` آماده کنید. بسته باید یک ریشه `ai-content-manager/` و فایل `ai-content-manager.php` در آن داشته باشد.

۳. بسته را به‌صورت دستی در بخش افزونه‌های WordPress نصب و فعال کنید. فعال‌سازی مجوز مدیریت افزونه را برای مدیر ثبت می‌کند. نسخه ۰.۷.۰ مهاجرت افزایشی و قابل تکرار ۱.۳.۰ به ۱.۴.۰ دارد: دو جدول کمپین/تلاش و شش ستون صف اضافه می‌شوند؛ هیچ ردیف قدیمی پاک یا بازنویسی نمی‌شود. نسخه دیتابیس فقط پس از تأیید ستون‌ها و ایندکس‌ها ارتقا می‌یابد. این مهاجرت روی دیتابیس واقعی در محیط حاضر اجرا نشده است.

۴. تنظیمات موردنیاز را فقط در رابط مدیریت همان سایت وارد کنید. کلید واقعی، خروجی صف، تنظیمات سایت، cookie یا اطلاعات اتصال را در مخزن یا گزارش‌ها نگذارید. Yoast و WPML اختیاری‌اند و نبودشان مطابق محدودیت هر مسیر گزارش می‌شود. هیچ کلید یا اطلاعات ورود واقعی همراه سورس نیست.

این دستورها خودشان نصب، اتصال به سایت یا درخواست OpenAI اجرا نمی‌کنند.

## اجرای آزمون‌های محلی

با PHP CLI در ریشه مخزن اجرا کنید؛ این مجموعه‌ها fixture هستند و به WordPress یا MySQL واقعی نیاز ندارند:

```sh
php tests/generation.php
php tests/admin.php
php tests/security-budget.php
php tests/workflows.php
php tests/seo.php
php tests/seo-bootstrap.php
php tests/category.php
php tests/category.php --wpml4
php tests/campaigns.php
php tests/migration.php
php tests/topic-admission.php
php tests/web-research-actions.php
php tests/seo-bootstrap.php --cron
node tests/admin-assets.js
```

برای lint تمام فایل‌های PHP در PowerShell:

```powershell
$files = @(Get-ChildItem ai-content-manager.php, includes, tests -Recurse -File -Filter *.php)
foreach ($file in $files) {
    php -l $file.FullName
    if ($LASTEXITCODE -ne 0) { throw 'خطای نحوی PHP' }
}
git diff --check
```

در آماده‌سازی این نسخه، **۵۵۰ بررسی PHP** با PHP CLI نسخه ۸.۵.۱۲، lint **۵۴ فایل PHP** و شش گروه آزمون JavaScript موفق بوده‌اند. مجموعه دسته‌بندی ۷۱ بررسی دارد و همان مجموعه با قرارداد WPML ۴ نیز جدا تکرار می‌شود؛ تکرار آن تست مستقل واقعی نیست. `tests/campaigns.php` و `tests/topic-admission.php` از PDO SQLite در حافظه برای اجرای SQL، یکتایی و rollback استفاده می‌کنند؛ advisory lock و `FOR UPDATE` واقعی MySQL، WordPress، HTTP، WPML و Yoast شبیه‌سازی‌اند. افزونه PDO SQLite برای این مجموعه لازم است. تست migration فقط قرارداد DDL و ارتقای نسخه را با recorder آزمایش می‌کند؛ اجرای واقعی `dbDelta` نیست. `tests/seo-bootstrap.php` ورودی و autoloader واقعی افزونه را با hookهای fixture آزمایش می‌کند و با `--cron` ثبت worker خارج از مدیریت را می‌سنجد؛ اجرای HTTP واقعی `admin-post.php` یا `wp-cron.php` نیست. هیچ درخواست واقعی OpenAI انجام نشده است.

تست واقعی WordPress/MySQL/Yoast، مرورگر و ویرایشگر واقعی، indexableهای Yoast، رقابت چندفرایندی و اجرای PHP ۷.۴ در این محیط انجام نشده‌اند. قفل افزونه، ویرایشگر عادی WordPress را قفل نمی‌کند؛ فاصله خواندن تا ذخیره metadata با ویرایش خارجی اتمیک نیست.

## ساخت ZIP محلی

در PowerShell از ریشه پروژه اجرا کنید:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-zip.ps1
```

این فرمان مجوز اجرای اسکریپت را فقط برای همان فرایند تعیین می‌کند و سیاست سیستم را تغییر نمی‌دهد. اسکریپت، ZIP قبلی محلی را جایگزین می‌کند؛ به شبکه یا سایت وصل نمی‌شود. فایل اصلی، `includes/`، `assets/`، `tests/`، README، سند مدل کمپین و گزارش‌های انتشار با فهرست مجاز بسته‌بندی می‌شوند و SHA-256 تمام اعضای بسته با سورس تطبیق داده می‌شود. `.git`، تنظیمات شخصی، ابزارهای محلی و اسرار وارد بسته نمی‌شوند.

خروجی `ai-content-manager.zip` با `.gitignore` کنار گذاشته می‌شود. نسخه جدید ZIP در Git ثبت نمی‌شود؛ ZIP قدیمی در commit اولیه برای حفظ تاریخچه باقی می‌ماند. حذف ZIP از index، فایل محلی را حذف نمی‌کند و محتوای تاریخی را پاک نمی‌کند. پیش از ارسال هر تاریخچه، ZIPهای موجود در آن هم باید بررسی شوند.

## تنظیم و بررسی کمپین

۱. فقط در سایت آزمایشی مستقل، مجوزهای مالک و دسته‌بندی هم‌زبان را بررسی کنید. مدل کمپین `gpt-6-luna` با Responses، خروجی ساختاریافته و `web_search` است؛ مدل تولید دستی تغییر نکرده است. وجود کلید تضمین دسترسی حساب به مدل نیست. مبنا [مستند مدل](https://developers.openai.com/api/docs/models/gpt-6-luna)، [جست‌وجو](https://developers.openai.com/api/docs/guides/tools-web-search) و [قیمت‌گذاری رسمی](https://developers.openai.com/api/docs/pricing) در ۲۰۲۶/۱۱/۱۱ است.

۲. نرخ ورودی/خروجی هر میلیون توکن و جست‌وجو هر هزار فراخوانی را با حساب خود بررسی و صریحاً تأیید کنید؛ تأیید حداکثر سی روز معتبر است. پیشنهاد محافظه‌کارانه: ۰٫۲۰ و ۰٫۷۵ دلار برای توکن و ۱۰ دلار برای هزار جست‌وجو. توکن جست‌وجو جدا منظور می‌شود. این اعداد صورتحساب قطعی نیستند؛ نرخ حساب، منطقه، تخفیف یا تغییر سرویس می‌تواند متفاوت باشد. دامنه‌های معتبر را می‌توان محدود کرد؛ تنظیم دامنه برای کمپین تازه ذخیره می‌شود. تغییر نرخ، پیش از درخواست تازه کمپین قبلی را متوقف می‌کند تا برآورد تازه تأیید شود.

۳. در «تولید محتوا» حالت خودکار، نوع نوشته، یک عبارت کلیدی، زبان، دسته‌بندی، لحن و طول تقریبی را انتخاب کنید؛ موضوع دستی لازم نیست. پیش‌فرض سه مقاله، سقف یک دلار و سه فراخوانی OpenAI برای هر مقاله است. سقف موضوع‌یابی دو درخواست جداگانه است. ایجاد فقط کمپین غیرفعال می‌سازد. ترجمه، تصویر و سیاست انتشار فرم برای کمپین اجرا نمی‌شوند؛ خروجی همیشه draft است.

۴. در مدیریت صف، برآورد تعداد درخواست و رزرو محافظه‌کارانه را ببینید و checkbox شروع/ادامه را صریحاً انتخاب کنید. برنامه معمول سه مقاله هفت درخواست OpenAI و شش دریافت منبع دارد؛ تعداد واقعی ممکن است با تلاش مجدد یا موضوع کمتر تفاوت کند. هر درخواست پژوهش حداکثر یک فراخوانی ابزار دارد. برآورد حداکثر بر پایه سقف ورودی، خروجی و تا ۱۳۱۰۷۲ توکن اضافی جست‌وجو است؛ سقف دلاری می‌تواند قبل از تکمیل هدف اجرا را متوقف کند. نرخ نامعتبر یا مصرف نامشخص، صفر تلقی نمی‌شود.

۵. توقف، درخواست تازه را متوقف می‌کند؛ پاسخ و مصرف درخواست شروع‌شده حفظ می‌شوند. ادامه نتیجه ذخیره‌شده را بدون API تکراری اعمال می‌کند. timeout مبهم نیازمند بررسی، فاصله امن و تأیید احتمال هزینه دوباره است؛ رزرو قبلی خودکار آزاد نمی‌شود. خطای پژوهش به تولید بدون پژوهش تبدیل نمی‌شود. شکست دسته یا سئو فقط همان مرحله و همان پیش‌نویس را نگه می‌دارد. تغییر دستی دسته/Yoast خودکار بازنویسی نمی‌شود.

۶. لینک ویرایش، دسته فعلی/انتخابی، منابع و شواهد را در صف بررسی کنید. یافتن نقل‌قول در صفحه اثبات درستی ادعا یا اعتبار منبع نیست؛ بررسی انسانی ضروری است. معیار نسخه ۰.۷.۱ پرسش اصلی و زاویه را با بخش‌های کوتاه مرتبط حداکثر پانصد ردیف صف و نوشته مقایسه می‌کند. کلمه کلیدی و قصد کلی به‌تنهایی دلیل رد نیستند؛ امضا نیز مبتنی بر پرسش نرمال‌شده است. معیار محلی تضمین کشف همه شباهت‌های معنایی، ترجمه‌شده یا چندزبانه ندارد. بالاتر از سقف corpus، پذیرش متوقف می‌شود. تعداد کمتر صریح گزارش می‌شود.

برای کمپین متوقف در پذیرش، «پیشنهادهای ذخیره‌شده موضوع‌یابی» را باز کنید. نسخه ۰.۷.۰ علت تاریخیِ تک‌تک ردها را نگه نمی‌داشت؛ از پیام کلی آن نباید تکراری‌بودن را نتیجه گرفت. «بررسی مجدد خروجی ذخیره‌شده؛ بدون هزینه» فقط با داده فعلی گزارش تازه می‌سازد و کمپین یا صف را فعال نمی‌کند. پس از بررسی، ادامه کمپین همان خروجی را دوباره زیر قفل کنترل و در صورت پذیرش وارد صف می‌کند؛ نخستین مرحلهٔ پذیرش شبکه ندارد، مراحل بعدی پژوهش/تولید هزینه‌دارند و تأیید جداگانه ادامه لازم است. اگر همه پیشنهادها در گزارش رد باشند، موضوع‌یابی تازه فقط با فرم هزینه‌دار جدا، قیمت معتبر، بودجه و سقف دو تلاش کل کمپین ممکن است. این سقف با بررسی مجدد بازنشانی نمی‌شود. امضاها، خروجی و مصرف قدیمی بازنویسی یا پاک نمی‌شوند؛ مهاجرت دیتابیس تازه‌ای اضافه نشده است.

راهنمای بررسی پذیرش، محدودیت‌ها و فایل‌های اصلاح در [گزارش ۰.۷.۱](RELEASE-0.7.1.md)، راهنمای Cron در [گزارش ۰.۷.۰](RELEASE-0.7.0.md) و مدل داده در [سند کمپین](DESIGN-CAMPAIGNS.md) آمده است. این دستورها مجوز اجرای پولی روی سایت اصلی نیستند.

## وضعیت صفحه سفید و آزمون واقعی

**علت قطعی صفحه سفید گزارش‌شده سایت هنوز مشخص نیست و رفع قطعی آن ادعا نمی‌شود.** کاربر بازشدن اخیر صفحه مقایسه را تأیید کرده است؛ ارسال نهایی فرم در محیط واقعی توسط ما آزمایش نشده است.

در نسخه ۰.۶.۱، استفاده از آدرس HTML‌شده در هدر redirect اصلاح شده و شکست بازگشت، nonce/مجوز نامعتبر و خطاهای قابل مدیریت پیام فارسی و لینک بازگشت دارند. همچنین فیلد نامعتبر دیگر به‌صورت ضمنی از نتیجه حذف نمی‌شود تا خطا پشت پیام موفقیت پنهان نماند. این اصلاح‌ها، علت صفحه سفید واقعی سایت را اثبات نمی‌کنند.

راهنمای گام‌به‌گام بررسی عبارت قدیمی، متای برابر، حفظ مقدار دستی، تعارض، POST و redirect و اطلاعات لازم برای تشخیص در [گزارش نسخه ۰.۶.۱](RELEASE-0.6.1.md) آمده است. برای بازتولید واقعی، نسخه‌های دقیق PHP/WordPress/Yoast، مرحله شکست، زمان، وضعیت HTTP و خطای PHP با نام فایل و خط لازم‌اند. nonce، کلید، cookie، header احراز هویت و متن خصوصی را از هر گزارش ارسالی حذف کنید.

## دسته‌بندی پیش‌نویس و WPML

انتخاب خالی فقط به معنی نداشتن انتخاب در صف است؛ دسته پیش‌فرض وردپرس حذف نمی‌شود. انتخاب حذف‌شده، ناسازگار با نوع محتوا/زبان یا بدون مجوز، پیام خطا می‌دهد و فرم حفظ می‌شود. انتخاب ناسازگار با تغییر زبان یا نوع محتوا نیز در مرورگر بی‌صدا پاک نمی‌شود. بدون JavaScript، زبان گزینه‌ها در برچسب مشخص است و سرور همان کنترل‌ها را انجام می‌دهد.

برای انتخاب قدیمی صف در زبان دیگر، فقط ترجمه موجود همان دسته با API رسمی WPML پیدا می‌شود؛ نبود ترجمه به خطا منتهی می‌شود و دسته تصادفی یا تازه ساخته نمی‌شود. قبل از اجرای hook زبان روی پیش‌نویس تازه، وضعیت اولیه دسته‌بندی در `payload.category_attempt` همراه شناسه نوشته، نشان پایدار، زبان و انتخاب متناظر ثبت می‌شود. این اطلاعات برای تلاش مجدد امن‌اند؛ `payload.category` اصلی تغییر نمی‌کند. اگر دسته‌بندی پس از شکست دستی تغییر کرده باشد یا پیش‌نویس قدیمی چنین سابقه‌ای نداشته باشد، جایگزینی خودکار متوقف می‌شود.

برای readyهای قبلی، «بررسی یا تکمیل پیش‌نویس» فقط عدم تطابق را گزارش می‌کند؛ اصلاح از پیوند مستقل «بررسی و اصلاح دسته‌بندی» و تأیید صریح انجام می‌شود. این اصلاح متن مقاله، زبان، Yoast، وضعیت انتشار یا مصرف OpenAI را تغییر نمی‌دهد. راهنمای تست دستی، بازتولید با کد قدیمی و محدودیت‌های تست واقعی در [گزارش نسخه ۰.۶.۲](RELEASE-0.6.2.md) آمده است. علت قطعی گزارش دسته‌بندی سایت بدون بازتولید روی همان محیط هنوز مشخص نیست.

## نگهداری سورس و امنیت

فایل‌های `.env`، `wp-config.php`، کلیدها، dump دیتابیس، backup، log، HAR، cache و تنظیمات شخصی IDE در Git قرار نمی‌گیرند. `.gitignore` فایل tracked یا اسرار تاریخی را حذف نمی‌کند. پیش از commit فهرست staged و diff و پیش از push فایل‌ها و تاریخچه قابل ارسال را جدا بازبینی کنید. بررسی الگویی تضمین نبود همه انواع اسرار نیست؛ اگر کلید واقعی پیدا شد، ارسال را متوقف کنید و بدون تصمیم صاحب مخزن تاریخچه را بازنویسی نکنید.

هیچ GitHub Actions، webhook یا تنظیمی برای انتشار روی WordPress اضافه نشده است. PR فقط برای بررسی سورس است؛ merge، نصب افزونه و تغییر visibility خودکار انجام نمی‌شوند. ورود Git محلی و دسترسی اتصال GitHub در ChatGPT مستقل‌اند و باید جدا تأیید شوند.
